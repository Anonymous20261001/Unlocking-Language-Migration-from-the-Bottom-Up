# 分析：为什么 C# 与 Java 最相近，编译通过率却最低（v2 修正版）

## 数据支撑的 vs 未支撑的

### 有数据支撑

1. **错误性质对比（最强证据）**
   同 1754 基准：C# 前 5 错误为 CS1056 意外字符(1222)、CS0246 类型不存在(1171)、
   CS1525 无效表达式(1130)、CS0103(881)、CS0525 接口含字段(539)——
   4/5 是词法/语法/声明级。C++ 前 10 错误全部是语义级（类型转换、重载缺失）。

2. **规则迁移（Java 规则 + C# 语法）**
   - CS0525 (539次): 300/300 抽样确认——在 interface 里写 `const int ABORT = 0x80;`
     （Java 接口允许常量，C# 禁止）。LLM 用的是合法 C# 关键字，违反的是 C# 规则。
   - CS0708/0710: 21 个单元 100% 命中——`static class Double` 带实例构造/成员
     （Java 工具类模式的直接迁移）。

3. **名字沿用（Java 类型/方法名进入 C#）**
   - CS0246 类型名: Java 名 17%、.NET 名 8%、其他 75%
   - CS0103 名字: Java 名 37%、.NET 名 20%、其他 43%
   - 例: `ConcurrentSkipListMap`、`DefaultListModel`、`DataBufferFloat`、`Biginteger`

### 没有数据支撑（需撤回）

1. ~~"约 60% 的错误可归因于按 Java 方式写 C#"~~ —— 未系统测量，撤回。
2. ~~"照搬（逐字复制）是主机制"~~ —— 逐字残留只占 2.4% 单元。
   真实机制是**规则迁移 + 名字沿用**，不是逐字复制。

## 修正后的解释

C# 失败由三类机制构成（按错误出现次数粗估）：

| 机制 | 证据 | 量级 |
|---|---|---|
| 规则迁移（Java 规则用 C# 语法写） | CS0525 (539) + CS0708/0710 + CS1519 using-in-class | ~8% |
| 名字沿用（Java 类/方法名沿用） | CS0246 的 17% + CS0103 的 37% | ~6% |
| 逐字复制 | `>>>`、`boolean`、`using java.`、`@Test` | 2.4% 单元 |
| 通用生成错误（幻觉名、截断、散文混入、重复成员） | 其余 | 大部分 |

## 结论（诚实版）

数据**支持**的结论只有两条：
1. C# 的错误在**词法/语法/声明层**，C++ 的在**语义层**——这是可测的事实。
2. 同名陷阱的三种形态（规则迁移/名字沿用/逐字复制）合计可量化解释
   **~15-17%** 的 C# 错误，不是多数。

因此"相似性导致低通过率"的机制**部分成立**：相似性确实诱导了
Java 规则与名字的迁移（这是 C++ 没有的失败来源），但它不是 C# 低通过率
的主因。主因仍是 LLM 的通用生成质量问题（幻觉、截断、重复），只是这些
问题在 C# 里表现为词法/语法错误，在 C++ 里表现为语义错误。
